# Reverse API


## 参数

- `$ARGUMENTS`：项目路径和选项
  - `--output=PATH`：输出路径（默认 docs/{project}/20_API_SPEC.md）
  - `--format=FORMAT`：输出格式（markdown | openapi，默认 markdown）
  - `--framework=NAME`：指定框架（自动检测或手动指定）

## 用法

```
/reverse-api ./my-backend
/reverse-api ./my-backend --format=openapi
/reverse-api ./my-backend --framework=express
```

## 支持的框架

| 框架 | 路由检测方式 | 支持程度 |
|------|-------------|----------|
| Express | `app.get/post/...` 或 `router.get/post/...` | ✅ 完整 |
| Koa | `router.get/post/...` | ✅ 完整 |
| NestJS | `@Get/@Post/...` 装饰器 | ✅ 完整 |
| Fastify | `fastify.get/post/...` | ⚠️ 基础 |
| Hono | `app.get/post/...` | ⚠️ 基础 |

## 执行步骤

### 1. 检测框架类型

```
读取 package.json 检测：
  - express → Express
  - koa + @koa/router → Koa
  - @nestjs/core → NestJS
  - fastify → Fastify
  - hono → Hono

如果无法检测：
  提示用户使用 --framework 指定
```

### 2. 定位路由文件

```
根据框架类型查找路由文件：

Express/Koa:
  - src/routes/**/*.{js,ts}
  - src/router/**/*.{js,ts}
  - routes/**/*.{js,ts}
  - app.{js,ts}（包含路由定义）

NestJS:
  - src/**/*.controller.ts
  - src/**/*.controller.js

通用模式:
  - 查找包含 router/route/controller 的文件
```

### 3. 解析路由定义

```
对每个路由文件，提取：

route_info:
  method: GET | POST | PUT | DELETE | PATCH
  path: "/api/users/:id"
  handler: "getUserById"
  file: "src/routes/user.ts"
  line: 42

# 尝试推断更多信息
  params: [{name: "id", type: "string", in: "path"}]
  query: [{name: "page", type: "number", in: "query"}]
  body: {推断自 TypeScript 类型或 Zod schema}
  response: {推断自返回类型}
```

### 4. 提取请求/响应类型

```
如果是 TypeScript 项目：
  查找相关类型定义：
    - 函数参数类型
    - req.body 的类型
    - 返回值类型

如果有 Zod/Joi 验证：
  解析 schema 定义

如果无法推断：
  标记为 confidence: low
  添加 TODO: 需要人工补充
```

## 置信度说明

```
置信度计算规则：

高 (≥0.8)：
  - 有 TypeScript 类型定义
  - 有 Zod/Joi 验证 schema
  - 有 JSDoc 注释

中 (0.5-0.8)：
  - 能推断参数名和基本类型
  - 但缺少完整类型定义

低 (<0.5)：
  - 只能识别路由路径和方法
  - 参数和响应类型未知
```

## 错误处理

```
如果没有找到路由文件：
  ❌ 未找到路由定义

  已搜索的位置：
  - src/routes/
  - src/router/
  - routes/

  建议：
  1. 确认项目包含 API 端点
  2. 使用 --framework 指定框架类型
  3. 手动创建 20_API_SPEC.md

如果框架不支持：
  ⚠️ 框架 {framework} 暂不支持自动逆向

  建议：
  1. 手动创建 API 文档
  2. 或提交 Issue 请求支持
```

## 注意事项

1. **只读操作**：不会修改源代码
2. **[逆向] 标记**：所有生成内容需人工验证
3. **不作为 Gate 依据**：逆向结果仅供参考，不能自动通过 Gate
4. **隐私保护**：不会读取 .env 或敏感配置

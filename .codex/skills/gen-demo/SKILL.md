# Gen Demo


## 参数

- `$ARGUMENTS`：功能模块名称（如 `user-auth`、`payment-system`）

## Demo 定位

Demo 是**轻量级交互验证**，用于：
- 快速验证 UI 布局和交互流程
- 与团队/用户确认需求理解
- 作为前端开发的参考文档

Demo **不是**代码原型，前端开发时参考 Demo 重新实现。

## 执行步骤

### 1. 验证参数

如果 `$ARGUMENTS` 为空，请提示用户：
```
请提供功能名称，例如：/gen-demo user-auth
```

### 2. 检查功能目录

检查 `docs/{feature-name}/` 是否存在：
- 如果不存在，提示先执行 `/new-feature {feature-name}`

检查 `docs/{feature-name}/_demos/` 是否存在：
- 如果不存在，创建该目录

### 3. 读取设计文档

按顺序查找以下文件：
1. `docs/{feature-name}/21_UI_FLOW_SPEC.md` - UI 流程规格（首选）
2. `docs/{feature-name}/40_DESIGN_FINAL.md` - 设计文档（备选）
3. `docs/{feature-name}/10_CONTEXT.md` - 功能上下文（最小输入）

如果都不存在，提示：
```
❌ 未找到设计文档
请先完成 Kickoff 或 Spec 阶段，再生成 Demo。
```

### 4. 分析设计文档

从设计文档中提取：
- **页面结构**：有哪些页面/区块
- **数据展示**：需要展示什么数据
- **交互流程**：用户操作流程
- **状态变化**：不同状态的 UI 表现

### 5. 生成 Demo HTML

在 `docs/{feature-name}/_demos/` 目录下生成 HTML 文件：

**命名规则：**
- `v1_initial.html` - 初版
- `v2_with_xxx.html` - 迭代版本（说明改进点）
- `final.html` - 确认版本

## 注意事项

- Demo 是**参考文档**，不是代码原型
- 使用原生 HTML/CSS/JS，不依赖框架
- Mock 数据直接写在 HTML 中
- 支持快速迭代，每个版本独立文件
- 前端开发时参考 Demo，而非复制代码

## 1. 文档定位

本文档定义 Codex 在本项目中的执行授权边界，用于减少低风险高频确认，同时确保高风险动作仍由人工把关。

适用范围：
- 命令执行
- 网络访问
- Git 写操作
- 启动服务
- 依赖安装
- 数据库读写
- 脚本运行

说明：
- 本文档定义的是项目策略，不绕过 Codex 平台自身权限机制
- 平台层需要审批时，仍按平台机制申请
- 本文档主要用于帮助 Codex 判断何时自动执行、何时申请一次性授权、何时申请可复用前缀授权、何时必须强确认

## 2. 三维分类模型

### 2.1 环境分类

| 环境 | 说明 | 风险级别 |
|------|------|----------|
| local-dev | 本地开发环境 | 低 |
| local-test | 本地测试环境 | 低到中 |
| shared-dev | 共享开发环境 | 中 |
| shared-test | 共享测试环境 | 中到高 |
| staging | 预发布环境 | 高 |
| production | 生产环境 | 极高 |

### 2.2 动作分类

| 动作 | 说明 |
|------|------|
| read-only | 只读查询 |
| service-control | 启动或停止服务 |
| safe-write | 工作区内非破坏性写入 |
| data-write | 插入、更新测试数据 |
| destructive | 删除、重置、覆盖、改 schema |
| external-side-effect | 对外部系统产生真实副作用 |

### 2.3 入口分类

| 入口 | 说明 |
|------|------|
| project-script | 项目固定脚本 |
| native-command | 原生命令 |
| seed-script | 固定 seed / reset 脚本 |
| arbitrary-shell | 任意 shell 组合命令 |
| raw-sql | 手写 SQL |

## 3. 授权等级

### 3.1 A 类：默认放行

适用于：
- 工作区内只读命令
- 文档读取与代码搜索
- 工作区内低风险文件修改
- 只读测试、静态检查、编译检查

### 3.2 B 类：允许可复用前缀授权

适用于：
- 本地开发服务启动
- 本地测试执行
- 依赖安装
- Git 提交类动作

原则：
- 优先对白名单脚本授权
- 不对白名单宽泛解释器或数据库客户端授权

### 3.3 C 类：逐次确认

适用于：
- 本地数据库插入测试数据
- 重置本地测试数据
- 共享 dev/test 环境的数据写入
- 批量导入导出测试数据

### 3.4 D 类：强确认且不做持久放权

适用于：
- 删除、覆盖、回滚、强制重置
- 任意手写 SQL 改库
- schema destructive 变更
- staging / production 环境操作
- 对外系统真实副作用

## 4. 开发与测试场景细化

### 4.1 本地开发启动

推荐等级：`B`

建议：
- 优先通过项目脚本启动，而不是直接授权整个 `mvn`
- 如果项目必须使用 Maven 启动，建议封装为固定脚本后再授权

建议脚本：
- `scripts/dev/run-app.sh`
- `scripts/dev/stop-app.sh`

### 4.2 本地测试执行

推荐等级：`A` 或 `B`

规则：
- 纯只读测试：可按 `A`
- 需要启动测试服务：按 `B`
- 需要写测试数据：提升到 `C`

建议脚本：
- `scripts/test/run-unit.sh`
- `scripts/test/run-integration.sh`

### 4.3 数据库测试数据写入

推荐等级：`C`

规则：
- 本地临时测试库：可逐次确认
- 共享 dev/test：必须逐次确认
- staging / production：禁止自动授权

建议：
- 只允许固定 seed 脚本
- 不允许给 `mysql`、`psql` 这类客户端宽泛持久授权

建议脚本：
- `scripts/dev/seed-local-db.sh`
- `scripts/dev/reset-local-db.sh`
- `scripts/test/seed-test-db.sh`

### 4.4 数据库 destructive 操作

推荐等级：`D`

包括但不限于：
- 删除数据
- truncate
- drop
- 手工执行改表 SQL
- 重置共享数据库

## 5. 推荐授权白名单

### 5.1 推荐持久授权的窄前缀

- `git add`
- `git commit -m`
- `git push target`
- `scripts/dev/run-app.sh`
- `scripts/test/run-unit.sh`
- `scripts/test/run-integration.sh`

### 5.2 不推荐持久授权的宽前缀

- `mvn`
- `bash`
- `sh`
- `python`
- `mysql`
- `psql`
- `node`

原则：
- 越通用的入口，越不适合持久授权
- 越接近固定脚本，越适合作为白名单入口

---

## 6. 永不自动授权清单

以下动作默认不进入自动授权范围：
- 工作区外任意写入
- 删除类命令
- 强制 Git 回滚
- 任意 SQL 改库
- schema destructive 迁移
- staging / production 环境操作
- 涉及真实扣费、通知、推送、消息发送的动作
- 涉及密钥、凭证、大规模导出的动作

## 7. Codex 执行策略

Codex 在执行前应按以下顺序判断：
1. 判断当前环境
2. 判断动作类型
3. 判断入口是否受控
4. 判断是否可收敛为窄前缀授权
5. 判断是否应改成项目脚本
6. 决定自动执行、申请复用授权、逐次确认或拒绝自动放权

输出建议时至少应包含：
- 风险等级
- 授权建议
- 推荐前缀或脚本
- 不建议放权的原因
